# Production Deployment: Neon + Render + Vercel

This guide deploys the CRM monorepo with:

| Service | Role |
|---------|------|
| **Neon** | Serverless PostgreSQL database |
| **Render** | Express backend API (`backend/`) |
| **Vercel** | Next.js frontend (`frontend/`) |

## Monorepo layout

```
CRM_Project/
├── prisma/              # Schema + migrations (shared)
├── backend/             # Express API → deploy to Render
├── frontend/            # Next.js app → deploy to Vercel
├── render.yaml          # Render Blueprint
└── frontend/vercel.json # Vercel hints
```

Prisma Client is generated into `backend/node_modules/.prisma/client` (configured in `prisma/schema.prisma`) so cloud builds always find the client when Render uses `rootDir: backend`.

---

## Step 1: Neon database

1. Create a project at [neon.tech](https://neon.tech).
2. Create a database (e.g. `crm_db`).
3. Copy two connection strings from the Neon dashboard:
   - **Direct** — for local migrations/seed
   - **Pooled** (`-pooler` in host) — for Render runtime (recommended)

Append SSL if missing:

```
?sslmode=require
```

Example pooled URL:

```
postgresql://user:pass@ep-xxx-pooler.us-east-1.aws.neon.tech/neondb?sslmode=require
```

4. Run migrations locally once (from your machine):

```bash
# Set Neon direct connection URL
export DATABASE_URL="postgresql://...direct...?sslmode=require"

cd backend
npm install
npm run db:migrate:deploy
npm run db:seed
```

## Step 2: Render backend

### Option A — Blueprint (recommended)

1. Push the repo to GitHub.
2. Render Dashboard → **New** → **Blueprint**.
3. Connect the repository; Render reads `render.yaml`.
4. Set these secrets when prompted (sync: false in blueprint):

| Variable | Value |
|----------|--------|
| `DATABASE_URL` | Neon **pooled** connection string |
| `FRONTEND_URL` | `https://your-app.vercel.app` (set after Vercel deploy) |
| `API_URL` | `https://crm-api.onrender.com` (your Render service URL) |

`JWT_ACCESS_SECRET` and `JWT_REFRESH_SECRET` can be auto-generated by the blueprint.

### Option B — Manual web service

| Setting | Value |
|---------|--------|
| **Root Directory** | `backend` |
| **Runtime** | Node |
| **Build Command** | `npm ci && npm run build` |
| **Start Command** | `npm run start:prod` |
| **Health Check Path** | `/api/health` |

### Render environment variables

| Variable | Required | Example |
|----------|----------|---------|
| `NODE_ENV` | Yes | `production` |
| `DATABASE_URL` | Yes | Neon pooled URL |
| `JWT_ACCESS_SECRET` | Yes | long random string |
| `JWT_REFRESH_SECRET` | Yes | long random string |
| `FRONTEND_URL` | Yes | `https://your-app.vercel.app` |
| `API_URL` | Yes | `https://crm-api.onrender.com` |
| `PORT` | Auto | Set by Render (do not hardcode) |

`start:prod` runs `prisma migrate deploy` then starts the server — no manual migration step on deploy.

### Verify backend

```bash
curl https://crm-api.onrender.com/api/health
```

Expected: `{"success":true,"message":"CRM API is running",...}`

## Step 3: Vercel frontend

1. [vercel.com](https://vercel.com) → **Add New Project** → import Git repo.
2. **Root Directory**: `frontend`
3. Framework: **Next.js** (auto-detected)
4. Environment variable:

| Name | Value |
|------|--------|
| `NEXT_PUBLIC_API_URL` | `https://crm-api.onrender.com/api` |

5. Deploy.

6. Copy the Vercel URL (e.g. `https://crm-xxx.vercel.app`).
7. Update Render `FRONTEND_URL` to that URL (comma-separate preview URLs if needed):

```
https://crm-xxx.vercel.app,https://crm-xxx-*.vercel.app
```

For preview deployments, add each preview pattern or use your production URL only.

8. Redeploy Render backend so CORS picks up the new origin.

### Vercel build settings (if not auto-detected)

| Setting | Value |
|---------|--------|
| Root Directory | `frontend` |
| Build Command | `npm run build` |
| Install Command | `npm ci` |
| Output Directory | `.next` |

## Step 4: Post-deploy checklist

- [ ] `GET /api/health` returns 200 on Render
- [ ] Login at Vercel URL with `admin@crm.com` / `Password123!` (after seed)
- [ ] Dashboard loads with stats
- [ ] Browser Network tab shows API calls to Render (no CORS errors)
- [ ] JWT secrets are not default dev values

## Local production build test

Simulate a clean Render build:

```bash
cd backend
rm -rf node_modules dist
npm ci
npm run build
DATABASE_URL="your-neon-url" npm run start:prod
```

Simulate Vercel build:

```bash
cd frontend
rm -rf node_modules .next
npm ci
NEXT_PUBLIC_API_URL=http://localhost:4000/api npm run build
```

## Troubleshooting

### `PrismaClientInitializationError` / client not found

- Ensure `postinstall` and `build` both run `prisma generate`.
- Render **Root Directory** must be `backend`.
- Schema output path must be `../backend/node_modules/.prisma/client` (already set).

### Migrations fail on Neon

- Use **direct** (non-pooler) URL for `prisma migrate deploy` if pooled URL fails; or run migrations locally with direct URL.
- Ensure `?sslmode=require` is present.

### CORS errors from Vercel

- Set `FRONTEND_URL` on Render to exact Vercel origin (no trailing slash).
- Include `https://` protocol.

### Render build: TypeScript not found

- Build command must be `npm ci && npm run build` (not `npm ci --omit=dev`).

### Avatar uploads on Render

- Disk is ephemeral; avatar files are lost on redeploy. Use S3/Cloudinary for production file storage.
